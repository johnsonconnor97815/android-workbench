# 版本选择

先填写目标设备与功能清单，再查版本。推荐“符合本次需求的候选”，不要声称遍历了全部版本并找到全局最优。

每个候选保留：版本、来源链接和查询时间、来源中的具体机型/ROM/root 条件、涉及的功能、匹配点、差异与已知问题。区分官方说明、源码推断、用户报告、相关机型实测和目标机实测。最终分别记录资料推荐、原版基线通过、改版通过。

优先级按用户需求确定：用户指定版本先验证；有已知适用修复且无相关回归的版本可优先；最新版本是候选之一。不要为了尝试更多版本扩大原定功能范围。必需能力通过即可确认本次适配；可选能力未测明确保留。

## 有来源的例子

查询日期：2026-09-16 UTC。

- [Frida 17.18.0 release](https://github.com/frida/frida/releases/tag/17.18.0)，发布于 2026-09-09。这不是 Android 10 兼容性证明。
- [frida/frida #3738](https://github.com/frida/frida/issues/3738)：报告者在 Pixel 1 / Android 10 / Magisk 上称 `17.7.3` 可用，而 `17.8.0` 至其测试的 `17.9.6` spawn 报 `Failed to spawn: unable to pick a payload base`。
- 同一 issue 的[其他设备反馈](https://github.com/frida/frida/issues/3738#issuecomment-4407723583)称 Infinix Note 7 上 `17.7.3` 也不工作。这些均是用户报告，不能推出所有 Android 10 设备统一选 `17.7.3`，也不能据此判断未测试的 `17.18.0`。

对类似 Android 10 目标，先核实是否对应同一功能和环境，检查后续上游修复，提出候选，再到目标机建立基线。本项目没有 Android 10 实机验证记录。

## 失败分流

| 观察 | 下一步 |
| --- | --- |
| 连接不到 server | 检查设备、监听地址、转发、进程身份与运行哈希 |
| 原版与改版均注入失败 | 先隔离权限、SELinux 条件、客户端组合和测试探针 |
| Java bridge / API 缺失 | 适配探针，记录测试受阻，不判定系统不兼容 |
| 原版通过，改版失败 | 回查补丁组、生成资源、配套客户端和实际加载产物 |
| 官方产物可用，源码构建失败 | 定位工具链/依赖问题；必要时用同工具链无补丁构建对照 |
| 原版存在已定位的上游缺陷 | 保留失败基线，将修复单列并验证；不隐去该限制 |
| 候选耗尽或重复同因失败 | 暂停切版本，补齐证据或缺失条件 |
