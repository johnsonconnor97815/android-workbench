# 分开保留复制进度历史与阶段交付历史

复制过程需要保存尚未编译通过的中间代码，而开发分支需要可核验的阶段成果。采用一个检出在复制分支上的共享工程目录，按稳定文件组持续保存；开发分支自动接收经过约定验证的完整阶段候选，每阶段一笔提交，细粒度历史保留在复制分支。

这一选择沿用最终文件唯一写入负责人的并发方式，避免每个 Agent 各建工作树；代价是阶段发布必须记录来源增量基线、核对候选全部变化并验证实际合成树，不能直接合入最新复制分支。

按用户最新提出的实施负担要求，先独立交付同步本地提交与批量推送，复用标准 Git 和已有服务；阶段发布另行接入现有 MVP 流程，不成为备份的前置依赖。方案详见 [Git 保存设计](../app-replica-git-design.md)；自动保存与批量推送已接入源码，阶段发布尚未实现。
