# 架构和当前边界

多个 Session 连接同一账户的共享服务。服务持有持久队列和资源记录，执行进程负责完整场景；Skill 与 MCP 负责表达请求，不各自抢占手机。

## 插件边界

Android Workbench 以插件为产品边界，而不是以单个 Skill 为产品边界。`.claude-plugin/plugin.json` 是唯一维护的插件清单；`.codex-plugin/plugin.json` 是字节相同的 Codex 兼容镜像，由发布校验强制一致。`skills/android-workbench/SKILL.md` 是唯一自动加载入口，静态环境、权限审计、分析代理、Frida、APK 导出、APK 逆向与设备管理作为该 Skill 的组件分发。

`agents/` 中的 Claude Code 子代理只提供窄域分工：静态分析、设备场景和报告审计。子代理不拥有手机、ADB、Frida 或共享环境，也不能绕过队列；它们必须调用同一 Workbench MCP 服务。这样插件可以提供 Agent 入口，同时保持一个共享调度器和一套资源锁。

- 队列使用 SQLite 持久保存，支持任务去重、依赖、优先级、等待公平性、取消及证据索引。
- 同设备保持单一控制者。读写资源与父子路径会检查冲突；不同设备及独立本地任务可以并行。
- 场景检查点由原控制者插入一层兼容观察，前后验证现场。已存在 Hook 不因脚本返回“已启动”而自动释放设备。
- 命名产物可绑定后续输入；活动 Hook 场景支持多个只读订阅者；证据索引、保留策略和任务资源用量记录已进入服务状态。
- LLM 只参与合法候选排序。模型执行时不持有数据库控制锁，建议返回后重新检查现场和资源。
- 代码、关键输入和产物留存哈希；功能成功与清理成功分别记录。取消、崩溃和未知结果不自动重放设备动作。
- `analysis.recon` 记录样本结构线索；`analysis.plan`、`analysis.plan_update`、`analysis.plan_check` 保存固定的分析阶段和文件证据，检查输入变化、阶段顺序、审阅记录与最终报告。它们不会自动执行阶段或理解全部业务语义。
- Python 运行时按源码指纹独立安装；项目环境维护不会替换正在运行的调度器解释器。
- 项目清单显式引用本仓库的入口 Skill 组件或项目自己的扩展。不需要旧组件仓库，也不共享测试样本或用户凭据。

## 共享工具环境

新项目的 `toolchain.mode:shared` 将同机同账户的固定工具安装到 XDG data 目录下的 `android-workbench/toolchains/<锁文件指纹>/`。工具目录、Node/Rust/静态/MCP 锁文件和平台共同选择目录；升级锁文件得到另一个环境。项目可以显式按工具覆盖已有工作区；覆盖项失效不能悄悄使用另一个版本。旧项目更新登记时保留已登记环境中的现有静态工具，将其写成显式覆盖，不移动工具字节。工具查找、执行环境和调度锁使用同一组解析结果，任务登记时冻结这些绑定。

`toolchain.auto_install:true` 是新项目默认值。客户端通过 `requires_tools` 提交独立的 `tools.ensure` 准备任务，原分析依赖准备成功。准备操作持共享工具目录写锁；其他项目的工具调用和长驻分析 MCP 持读锁。缺失、损坏、功能复查失败和自定义版本缺少锁定安装器分别保留结果；修复不等于升级。调用底层服务 RPC 或从受管 worker 内提交新的任意分析时，不经过客户端自动准备，应先显式准备所需工具；禁止在持读锁的分析/MCP 内执行安装。

通用 Linux 工具的检查范围与 Frida、商业参考项和平台/目标版本限定工具分开。CLI/import、合成样本、真实 APK/Android ELF、MCP 协议和样本调用、真机 Hook 各自记录，不相互替代。MCP 的共享启动脚本只包含工具路径，Apktool 解码目录和 Ghidra 分析工程通过每个项目自己的配置传入，客户端配置和样本证据保留在项目中。

`devices.discover` 的 ADB/fastboot 探测并行且限时，不在外部命令运行期间持全局调度锁。服务保存探测期间的 ADB 环境读占用，环境写入继续等待；已有写入或故障占用时返回明确原因，不绕过队列执行。

以下完整设计能力仍未实现，不属于本次仓库独立化补齐的范围：

1. 交互场景提交后追加步骤。共享持续 Hook 的多订阅者管理已实现；场景步骤仍需在提交时固定且有有限时长。
2. 通用多阶段工作流。固定分析阶段的进度与完成检查已实现；按产物名称绑定已支持已登记的具体输入/输出链，但不提供任意阶段图、自动阶段执行或任意中途恢复。
3. 通用环境及分析工程修复。当前只提供已适配的只读重检和原生探针恢复；未知状态保留阻塞。
4. 自动证据合并、cgroup CPU/内存硬限制和全面设备热插拔处理。证据索引、保留策略和必要资源用量记录已实现。
5. 更广泛的真机与故障组合验证。本轮已在 `pixel-8ARXS06LU` 覆盖多页面观察、真实失败、恢复和旧部署回滚；这不等于所有机型、页面和故障组合都已验证。

协调范围是同一 Linux 主机、同一账户、同一共享服务中的受管入口。原始 ADB/Frida 绕过、人工触屏、多个账户和多个主机连接不受当前机制强制拦截。
