# 架构和当前边界

多个 Session 连接同一账户的共享服务。服务持有持久队列和资源记录，执行进程负责完整场景；Skill 与 MCP 负责表达请求，不各自抢占手机。

## 插件边界

Android Workbench 以插件为产品边界，而不是以单个 Skill 为产品边界。`.claude-plugin/plugin.json` 是唯一维护的插件清单；`.codex-plugin/plugin.json` 是字节相同的 Codex 兼容镜像，由发布校验强制一致。`skills/android-workbench/SKILL.md` 是唯一自动加载入口，静态环境、分析代理、Frida、APK 导出与 APK 逆向作为该 Skill 的组件分发。

`agents/` 中的 Claude Code 子代理只提供窄域分工：静态分析、设备场景和报告审计。子代理不拥有手机、ADB、Frida 或共享环境，也不能绕过队列；它们必须调用同一 Workbench MCP 服务。这样插件可以提供 Agent 入口，同时保持一个共享调度器和一套资源锁。

- 队列使用 SQLite 持久保存，支持任务去重、依赖、优先级、等待公平性、取消及证据索引。
- 同设备保持单一控制者。读写资源与父子路径会检查冲突；不同设备及独立本地任务可以并行。
- 场景检查点由原控制者插入一层兼容观察，前后验证现场。已存在 Hook 不因脚本返回“已启动”而自动释放设备。
- LLM 只参与合法候选排序。模型执行时不持有数据库控制锁，建议返回后重新检查现场和资源。
- 代码、关键输入和产物留存哈希；功能成功与清理成功分别记录。取消、崩溃和未知结果不自动重放设备动作。
- Python 运行时按源码指纹独立安装；项目环境维护不会替换正在运行的调度器解释器。
- 项目清单显式引用本仓库的入口 Skill 组件或项目自己的扩展。不需要旧组件仓库，也不共享测试样本或用户凭据。

以下完整设计能力仍未实现，不属于本次仓库独立化补齐的范围：

1. 交互场景后续追加步骤，以及共享持续 Hook 的多订阅者管理。当前场景提交时固定且有有限时长；进度订阅不是 Hook 订阅。
2. 通用多阶段工作流和按产物名称绑定后续输入。当前支持任务依赖和 APK 设备阶段提前释放。
3. 通用环境及分析工程修复。当前只提供已适配的只读重检和原生探针恢复；未知状态保留阻塞。
4. 自动证据合并、完整磁盘保留策略、CPU/内存硬限制和全面设备热插拔处理。
5. 更广泛的真机与故障组合验证。离线测试不证明具体机型 Hook 可用；真实 Hook 和检查点观察分别成功，也不等于其组合已经通过。

协调范围是同一 Linux 主机、同一账户、同一共享服务中的受管入口。原始 ADB/Frida 绕过、人工触屏、多个账户和多个主机连接不受当前机制强制拦截。
