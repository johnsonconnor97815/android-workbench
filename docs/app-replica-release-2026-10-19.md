# 2026-10-19 复制流程更新说明

本次更新的目的是减少复制过程中的重复分析、重复交付和相互等待，让已有代码更快进入组装与验证，同时保留未完成事项和原版核对要求。

更新对象是 **Android Workbench 的复制调度程序和角色工作规则**。本次没有修改 Avola 的方法实现，也没有增加它已经完成的函数数量。

- 实现提交：[`5f92936c1ce938ba69187c5d8474d89c5abc10bc`](https://github.com/johnsonconnor97815/android-workbench/commit/5f92936c1ce938ba69187c5d8474d89c5abc10bc)。
- 新能力标识：`status --summary` 返回 `delivery_protocol:2`。本次没有调整插件版本号，原有状态存储格式也没有批量迁移。
- 切换步骤与可直接转发的提示词：[同事升级指南](app-replica-delivery-upgrade.md)。

## 改了什么，为什么改

| 原来的问题 | 本次修改 | 预期效果 |
| --- | --- | --- |
| 方法源码已经写好，但还要等整合验证；组装者又在等方法交付，可能相互卡住。 | 允许先交付已完成且自查通过的源码，把组装、构建和运行验证登记给已有负责人。 | 源码可以及时进入下一步，未验证事项仍有明确记录。 |
| 恢复、停止或再次提交会改变任务版本，内容相同的旧成果也可能要求重新确认。 | 新交付按实际内容、所用依赖和检查依据判断能否复用；单纯的状态变化不再使内容失效。 | 减少没有实际变化却重复提交、重复核对的工作。 |
| 普通完成也要逐层通知、再安排一轮处理。 | 普通源码交付直接通知组装负责人；相同内容不重复通知。组装或构建证据齐备并确认停止后，由程序登记该待办完成。 | 减少只为转述进度或登记完成而启动的模型回合。 |
| 已有分析和类声明没有被优先利用，容易重复读取、解释和拆分。 | 更新角色规则：先查已有记录，确认原版文件、对象、问题和条件仍适用；有新疑点或变化才补分析。已有类负责人可连续处理同一类中紧密相关的小方法。 | 减少重复分析和不必要的交接。这是工作规则调整，不是新增自动分析缓存。 |
| 源码完成和整体验证混在一起，容易把后续问题漏掉。 | 后续待办单独保存；提交时省略它们也不会消失。相关代码或证据变化后，原验证会标为需要重新核对。 | 更容易区分“源码已交付”和“已经验证”，减少遗漏。 |

## 一个具体例子

某个方法已写完，自查通过，只剩“放进工程后核对运行结果”。以前，这条事项可能一直挡住方法交付，组装者因此拿不到可用成果。

现在，方法可以先交付给组装者，同时留下有负责人的运行待办。组装者继续整合；涉及 Android 运行的待办，仍须拿到指定条件下原版与复制版的实际比较证据，才能登记完成。**交付源码不等于整个 App 已经完成。**

如果随后只是任务停止、恢复，内容和检查依据没有变化，就继续使用原成果；如果方法代码、类声明、依赖或检查依据发生变化，仍须核对受影响部分。

## 预计有什么效果

预期减少三类时间：等别人登记完成的时间、内容没变却重复核对的时间、重复分析已有结论的时间。节省出来的工作量可以用于尚未实现的方法和必要验证。

目前没有同事采用新版后的对照数据，**不承诺固定提速比例或节省时长**。复杂方法、额度限制、设备和网络阻塞仍会影响进度。后续可根据现有记录观察：同内容重复交付是否减少、源码交付到组装的等待是否缩短、普通完成是否仍反复唤醒 App 负责人；比较实现速度时还需考虑方法难度。

## 已经验证到什么程度

在上述实现提交上，以下命令均成功，退出状态为 `0`：

- `python3 scripts/check.py`：四组共 **756 项测试通过**，其中包含插件构建检查。
- `python3 scripts/build_plugin.py --check`：插件文件检查通过。
- `claude plugin validate .`：插件验证通过。

测试覆盖内容复用与失效、依赖变化、活动写入者、旧记录兼容、待办归属与结项、运行比较范围和路径搬迁。使用的是临时工作区与宿主模拟，不能据此宣称 Avola 已构建、安装或与原版一致；也不代表同事的工作区已经升级。

## 同事如何采用

按[升级指南中的五段提示词](app-replica-delivery-upgrade.md#给同事的提示词)依次操作：停止新派发并确认旧工作者收尾，备份当前机器上的最新成果，更新项目实际使用的 Workbench，验证一个真实待办，再恢复原有单一调度器。

旧记录保留，不需要为了升级重跑全部已完成方法。新字段在下一次确有工作时采用。现有模型分工、并发配置、文件负责人和完整复制范围保持不变；未实现逻辑、失败或未知检查仍然阻止源码交付。写入新格式记录后，不要混用旧程序或直接降级继续写入。
